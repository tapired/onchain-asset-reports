# JOC vault and strategy permission-risk audit

> Publication copy of the November 1, 2026 fixed-block assessment. Values and role holders are historical snapshots. Supporting data has internal audit-server paths normalized; raw detail-page and verified-source captures are not included. See [Yearn evidence notes](./README.md).

**Snapshot date:** 2026-11-01, around 11:52:47–11:52:58 UTC. **Scope:** every JOC homepage vault and strategy link, including separate leveraged references, cross-checked against the default [Yearn vault catalog](https://yearn.fi/vaults). No transaction was submitted. Source pages and RPC reads were captured separately; site values are display estimates, while role and debt getters use the fixed blocks in [evidence.json](./evidence/strategies/evidence.json).

## Executive summary

- **A single 3-of-6 Safe controls the shared Katana LP beacon.** Nine JOC strategies use seven distinct LP proxies with the same [beacon](https://katanascan.com/address/0x834a0ec5347be6e62a1e57a01f1250c7ddde617a). The [owner Safe](https://katanascan.com/address/0xd9DB26176DD2A905aaF9213581366A5bb3913573) has a 3-of-6 threshold and no enabled modules at block 46,791,165. Read-only `eth_call` confirmed that `upgradeImplementationTo(address)` accepts a different deployed code address from that Safe and reverts from an unrelated caller. There is no timelock in this observed call path. A malicious implementation could act through each LP proxy and reach its pooled assets. The beacon itself lacks published source on Etherscan V2; its deployed selector, owner getter, implementation getter, proxy slots, and authorization behavior were checked onchain. [LP proxy source](https://katanascan.com/address/0x59719861Fc440A75D38202e5a297cFE68E149691#code), [current LP implementation](https://katanascan.com/address/0x8032D063992f4f6A14bC2be69a0D24CB563365de#code), [evidence](./evidence/strategies/evidence.json).
- **One EOA has an operational path across 15 active Ethereum JOC vaults.** [The EOA](https://etherscan.io/address/0x420acf637d662b80cca8befb327aa24039e7e0fa) is a current keeper on [yHaaSRelayer](https://etherscan.io/address/0x604e586F17cE106B64185A7a0d2c1Da5bAce711E#code) at block 26,319,744. The relayer holds `REPORTING` on all 16 vaults and is an authorized keeper of [DebtAllocator](https://etherscan.io/address/0x1e9eB053228B1156831759401dE0E115356b8671#code), which holds `DEBT` on all 16. Its `forwardCall` accepts caller-chosen target and calldata; `DebtAllocator.update_debt(vault,strategy,target)` checks keeper authorization but does **not** require `shouldUpdateDebt` to be true. The same EOA can call [TKSRelayerMulticall](https://etherscan.io/address/0x4e440bbc8d0a63fb53791fcb0375df8e58f41567#code), an authorized ratio manager, and change target/max ratios for approved strategies. Vault `max_debt`, available idle/liquidity, and approved strategy list still bind actual debt moves. [SKY-1](https://joc.yearn.dev/vault/ethereum/0xaF71a4f5d93fb88B24C67760BCF9688a6C3A54D4) is shutdown and its vault code forces new debt to zero, so this allocation path cannot fund its three zero-debt strategies. This is a large operational loss/freeze surface on the other 15 vaults; it is **not evidence of direct transfer to the EOA**. A no-change debt-move `eth_call` returned `false`, so successful movement for a particular target remains transaction-state dependent. [Fixed-block role rows](./evidence/strategies/roles.csv), [debt getters](./evidence/strategies/inventory.csv).
- **An EOA holds all 14 Yearn vault roles on Katana Woofy.** [The key](https://katanascan.com/address/0x1b5f15DCb82d25f91c65b53CEe151E8b9fBdD271) has role mask `16383` on [Woofy yVault](https://joc.yearn.dev/vault/katana/0x639bCcF37CC0415812A6f110CFCa33127a81c0e9) at block 46,791,165. `totalIdle()` equals `totalAssets()` (`43802965317001310` raw WOOFY; JOC displays **43.80K WOOFY**) and `totalDebt()` is zero. The key can add a compatible malicious strategy, raise its debt cap, and allocate idle funds immediately; it can also set a withdrawal-limit module to freeze exits. That is a concrete single-key path to all currently idle WOOFY. The USD value was not independently established. [Vault code](https://katanascan.com/address/0x639bCcF37CC0415812A6f110CFCa33127a81c0e9#code), [role rows](./evidence/strategies/roles.csv).
- **EOA keepers for five funded Katana LP strategies can invoke spot-priced rebalancing.** [The keeper](https://katanascan.com/address/0x420ACF637D662b80cca8bEfb327AA24039E7e0Fa) holds `KEEPER` on five funded [Katana `Strategy` implementations](./evidence/strategies/keeper_surface.csv). Their `tend()` reaches `_tend`, `_depositInLp`, `_withdrawFromLp`, and `_performSwap`. `_performSwap` uses the pool's spot price and a near-unbounded Uniswap price limit; LP deposits and withdrawals pass zero minimum amounts. `maxSwapValue` caps each swap but there is no cumulative cap, and `minTendWait=300` is checked in the advisory `_tendTrigger()`, not in `_tend()` or the [tokenized `tend()`](https://katanascan.com/address/0xD377919FA87120584B21279a491F82D5265A139c#code). Adverse pool/LP prices and a counterparty are needed for a realized trading loss. This is not an unrestricted token sweep by the keeper. ## What the roles can do

The [verified Yearn V3 vault code](https://etherscan.io/address/0xBe53A109B494E5c9f97b9Cd39Fe969BE68BF6204#code) implements a 14-bit role mask. The actual holder and role combination for each vault is in [roles.csv](./evidence/strategies/roles.csv). `ADD_STRATEGY` registers a matching-asset ERC-4626 strategy; `MAX_DEBT` sets its cap; `DEBT` calls `update_debt` and moves idle vault assets to an approved strategy or withdraws from it. A loss to an attacker-controlled recipient normally requires the combination of an approved malicious strategy and debt movement, or an already compromised approved strategy. `REPORTING` calls `process_report` and invokes the accountant; `ACCOUNTANT` can replace that module. `WITHDRAW_LIMIT` can select a module that blocks exits, `QUEUE` can alter withdrawal ordering, `DEPOSIT_LIMIT` can stop deposits, and `EMERGENCY` shuts down the vault and acquires `DEBT` for unwind. `FORCE_REVOKE` can realize/strand bad strategy debt as an accounting loss without directly transferring it to the caller. `MIN_IDLE`, `PROFIT_UNLOCK`, `REVOKE_STRATEGY`, and `DEBT_PURCHASER` have their source-specific effects and bounds in the CSV. These vault entrypoints have no built-in timelock; holder contracts can add delay.

The ordinary `ADD_STRATEGY` holder on every JOC vault except Woofy is [the cross-chain TimelockController](https://etherscan.io/address/0x88Ba032be87d5EF1fbE87336B7090767F367BF73#code). `getMinDelay()` is **604,800 seconds (7 days)** at each pinned chain block. [JOC's timelock page](https://joc.yearn.dev/timelocks) lists proposer, executor, canceller, and admin addresses; all 30 listed chain/role/holder pairs returned `hasRole=true` at the fixed blocks. The timelock is proposer-gated; execution cannot skip the scheduled minimum delay through the observed entrypoint. The [RoleManager](https://etherscan.io/address/0xb3bd6B2E61753C311EFbCF0111f75D29706D9a41#code) can change delegated roles through governance, while the already assigned `DEBT`, `REPORTING`, `EMERGENCY`, and other holder roles act without that new-strategy delay. [Controller reads](./evidence/strategies/controllers.json), [timelock reads](./evidence/strategies/timelock_roles.json).

The four Ethereum [MetaMorphoV1_1](https://etherscan.io/address/0x68Aea7b82Df6CcdF76235D46445Ed83f85F845A3#code) strategy vaults have a 4-of-7 owner Safe, a 2-of-3 curator Safe, a 6-of-9 guardian Safe, and `timelock()` of 259,200 seconds (3 days). Their market caps, allocator mapping, and pending changes require a separate current-state enumeration before any claim about the weakest Morpho market-movement path. [Fixed-block getters](./evidence/strategies/metamorpho_roles.json).

For the seven distinct Katana LP proxies, the [current LP implementation](https://katanascan.com/address/0x8032D063992f4f6A14bC2be69a0D24CB563365de#code) gives `MANAGER_ROLE` to an [Orchestrator proxy](https://katanascan.com/address/0x1c735adfe82133dda6a08b81b813e4d7aff3b32a) and `STEER_ROLE` to the same 3-of-6 Safe that owns the beacon. The LP manager can `tend` with position/swap calldata subject to a TWAP volatility check; `STEER_ROLE` can pause and `emergencyBurn`. All 14 observed LP role grants (two per LP) were event-enumerated and confirmed by `hasRole`. The orchestrator requires keeper-registry voting for ordinary `executeAction`, but the shared Safe also owns its ProxyAdmin and can upgrade the orchestrator without that vote. [LP role evidence](./evidence/strategies/lp_roles.json), [orchestrator implementation](https://katanascan.com/address/0x78cd87c92a469ffbc9badc26616233eed0a677a3#code).

## Keeper analysis

The [Yearn TokenizedStrategy implementation](https://etherscan.io/address/0xD377919FA87120584B21279a491F82D5265A139c#code) authorizes `report()` and `tend()` for keeper **or management**; `harvestAndReport()` and `tendThis()` callbacks are self-only in [BaseStrategy](https://github.com/yearn/tokenized-strategy/blob/master/src/BaseStrategy.sol). `shutdownStrategy()` and post-shutdown `emergencyWithdraw()` require management or emergency admin. Management can set the keeper and emergency admin, fee/recipient fields, and custom strategy controls. A base-layer keeper cannot select a transfer recipient through `report()` or `tend()` arguments. The custom callbacks determine whether a keeper can trade, borrow, report a manipulable value, or create a withdrawal bottleneck; [keeper_surface.csv](./evidence/strategies/keeper_surface.csv) lists every strategy URL and its custom keeper-callable functions from verified source.

The specific **freeze** paths established by source are the vault `WITHDRAW_LIMIT` module setter, `QUEUE` changes, `EMERGENCY` shutdown of deposits, Katana LP `STEER_ROLE.pause`, and dependence on timely LP/looper unwinds where normal `availableWithdrawLimit` can be low. A compromised keeper can refuse maintenance or invoke a bad `tend`; withholding alone is usually operational grief until management/Safe intervention. Whether a particular vault's user withdrawal is fully frozen needs a fixed-block redeem/queue simulation and liquidity trace; JOC's `Withdrawable` display is a separate emergency simulation and is not proof of normal exit liquidity.

## Zero-debt contingent exposure

The 39 exact-zero direct associations are not currently funded by their parent vault. Some strategies have nonzero `totalAssets()` or reward dust of their own; zero **vault debt** is the relevant current parent-fund exposure measure. A registered strategy with a nonzero `max_debt` can later receive idle vault funds from a `DEBT` holder without a new `ADD_STRATEGY` vote **if the vault is active**. The zero-debt Katana LP strategies managed by [the EOA](https://katanascan.com/address/0x787aba336583f4a1d4f8cbbfdffd49f3a38de665) have nonzero caps on vbETH, vbUSDT, and AUSD vaults. [AUSD](https://joc.yearn.dev/vault/katana/0x93Fec6639717b6215A48E5a72a162C50DCC40d68) is shutdown, so its caps cannot be used to increase debt under the verified vault code. Ethereum SKY-1 is likewise shutdown. The Base zero-debt EOA-managed Euler strategy has `max_debt=0` and needs a cap increase as well as debt allocation before parent vault funds are exposed. [Exact per-association caps and shutdown flags](./evidence/strategies/inventory.csv).

## Limitations and exact TODOs

1. **Base holder completeness:** Etherscan V2 returns “Free API access is not supported for this chain” for `logs.getLogs` on chain 8453, while the configured Base Alchemy RPC rejects `eth_getLogs` ranges over ten blocks. The two Base vaults' JOC-listed holders were checked with `roles(address)` at block 53,372,314, but unlisted holder enumeration is **TODO**. Restore paid Base event-history access or a configured Base archival RPC with practical log ranges; then scan `RoleSet` from deployment to the pinned block and confirm every candidate. The user was asked for this access. No public RPC fallback was used.
2. **External protocol roles:** The audit did not exhaustively enumerate role/admin/proxy trees of every Aave, Spark, Morpho market, Pendle, Stargate, PSM, CCTP bridge, and reward-auction dependency reachable from all 96 strategy URLs. **TODO:** per strategy, enumerate dependency addresses from its verified source/getters; read the current owner, proxy admin, oracle, cap setter, token minter, pause, and withdrawal gate; and link each full address and deployment block. Do not treat the role CSV as proof of exclusivity for those dependencies.
3. **Katana beacon source:** `getsourcecode` returned no source/ABI for the [beacon](https://katanascan.com/address/0x834a0ec5347be6e62a1e57a01f1250c7ddde617a). Its selector, ownership, current implementation, all seven LP beacon slots, and read-only upgrade authorization were verified. **TODO:** obtain the exact published beacon source or reproducible bytecode build to assess every alternative upgrade/admin path and whether any hidden delay or veto exists. The observed `upgradeImplementationTo` call itself succeeded without a delay check.
4. **Per-strategy custom keeper bounds:** [keeper_surface.csv](./evidence/strategies/keeper_surface.csv) is a source-derived entrypoint index, not a completed economic proof for every auction, swap, leverage, and oracle path. **TODO:** read current reward-token allowlists, route/solver targets, slippage setters, price oracles, approvals, and repeated-call limits for each custom family; simulate worst-case routes at the snapshot state. In particular, check spot manipulation cost and LP/pool liquidity for each funded Katana LP strategy before assigning a maximum extractable loss.
5. **Timelock and relay holder completeness:** The 30 timelock role candidates on JOC were onchain-confirmed, but complete `RoleGranted`/`RoleRevoked` histories were not reconciled for all five timelocks. yHaaSRelayer and TKS relay have eventless keeper mappings; the named EOA and controller candidates were getter-confirmed, while exhaustive historical transaction scans are **TODO**. This could reveal additional weaker keys. The Ethereum DebtAllocator's evented keeper/manager set was scanned, and the active managers/keepers in [debt_allocator_roles.json](./evidence/strategies/debt_allocator_roles.json) were getter-confirmed.
6. **Mixed-time reference data:** JOC/Yearn HTML and Etherscan source metadata were read around the pinned blocks, not historically queried at the exact block. Onchain debt, roles, code classifications, Safe thresholds, timelock delays, LP beacon slots, and key parameters use the fixed chain blocks. **TODO:** re-fetch site and source metadata if a later replay detects a same-day deployment or upgrade; re-read implementation slots at the historical block for every non-beacon proxy.
